## 结论要点（≤10 条）

1. **多样性重排的默认答案是 MMR**，α-NDCG / xQuAD 是评估侧的子主题覆盖指标，来源多样性、新颖性、时间衰减是排序侧的信号；三者可组合成"相关性 − 冗余 + 新颖 + 时效"的线性打分。出处：Carbonell & Goldstein SIGIR'98 [来源: https://doi.org/10.1145/290941.291025]、Clarke et al. SIGIR'08 [来源: https://doi.org/10.1145/1390334.1390446]、Santos et al. WWW'10 [来源: https://doi.org/10.1145/1772690.1772780]。
2. **"信息茧房"在 Facebook 上被官方数据部分证实，但直接改造排序并未显著改变态度**：算法排序使信息流中的跨立场内容减少约 15%、跨立场内容点击率降低约 70%（Bakshy et al. 2015）[来源: https://doi.org/10.1126/science.aaa1160]；但把 23,377 名 Facebook 用户切换到时间顺序后，曝光确实更"交叉"，八项预注册态度指标却无可测变化（Nyhan et al. 2023, Nature）[来源: https://doi.org/10.1038/s41586-023-06297-w]；Facebook/Instagram 时间序实验同样显示时间序**同时**增加了政治内容与不可信内容（Guess et al. 2023, Science）[来源: https://doi.org/10.1126/science.abp9364]。
3. **工程上"排序改造"收益有限，"排序前的选择"（候选集/配额）收益更大**：Twitter 的反向时间序 RCT（近 200 万日活）显示算法放大了右翼政治内容（7 国中 6 国主流右翼 > 主流左翼）[来源: https://doi.org/10.1073/pnas.2025334119]；预注册算法审计显示"按互动排序"会放大敌意内容、且**用户并不偏好算法选出的政治内容** [来源: https://doi.org/10.1093/pnasnexus/pgaf062]。
4. **可复用的工程模板**：X 开源推荐算法里已经包含了"多样性"所需的全部零件——SimClusters（社区发现+稀疏嵌入）、heavy-ranker（NN 排序）、visibility-filters（硬过滤/可见降权/粗粒度降排名）、tweetcred（PageRank 作者信誉）、representation-scorer（嵌入相似度）[来源: https://github.com/twitter/the-algorithm]。小红书自己发过 KDD'21 论文：用序列级信号（Sliding Spectrum Decomposition）+ 长尾友好的 item embedding 做"发现页"多样化，已服务数千万用户 [来源: https://arxiv.org/abs/2107.05204]。
5. **LLM 只用在"重排/摘要/聚类命名"，不要用在"实时召回"**：RankGPT（EMNLP'23）证明 LLM 可做零样本重排，并可用 permutation distillation 蒸馏成 440M 小模型，蒸馏模型在 BEIR 上超过 3B 监督模型 [来源: https://arxiv.org/abs/2304.09542]；工业界更常用"MMR 当老师蒸馏到轻量模型"（KDD'24，快手线上 A/B）[来源: https://arxiv.org/abs/2406.09021]。
6. **多样性不必然牺牲满意度**：两周真实用户在线部署的 MMR 重排实验显示 nDCG 与 coverage 显著提升，用户对"重排/未重排"**没有明显偏好差异** [来源: https://arxiv.org/abs/2507.21115]；论坛评论多样化实验中被试明确选择多样化版本，但该类主观判断的 Cohen's κ 仅约 0.2 [来源: https://arxiv.org/abs/2002.12457]。
7. **软广告有明确的法定形态可抓**：《互联网广告管理办法》第九条要求"通过知识介绍、体验分享、消费测评等形式推销商品或者服务，并附加购物链接等购买方式的，应当显著标明'广告'" [来源: https://www.gov.cn/zhengce/202305/content_6858084.htm]。所以"探店/测评体裁 + 购买链接/团购组件"本身就是法律上的广告信号，而"无任何标识"是平台失职点，优先按疑似违规处理。
8. **小红书软广的产业化有学术证据**：KOC（关键意见消费者）被品牌方雇佣产出"广告种草内容"，且**刻意伪装成普通用户的自发分享**以规避识别 [来源: https://arxiv.org/abs/2409.08360]。这意味着"读起来像真实体验"不能作为"是真实体验"的证据——必须依赖结构化字段与账号画像。
9. **纯提示词 LLM 分类器在小红书域内不可靠**：XHS-SCoRE 基准发现"生成—检测不匹配"，提示词式 LLM 分类器系统性失效，而中文编码器监督模型可行 [来源: https://arxiv.org/abs/2605.01017]。因此：规则/结构化信号 → 自训小模型 → LLM 只做**可选的**灰区复核或摘要，三层是合理分工（且 LLM 环节必须可插拔，无 key 时功能完整）。
10. **可直接复用的组件**（均已核实存在）：`feedparser`（RSS 解析）、`trafilatura`（正文抽取，topics 含 news-aggregator / article-extractor / llm）、`dedupe`（模糊匹配去重）、`datasketch`（MinHash/LSH）、`BERTopic`（主题聚类）、`leafac/kill-the-newsletter`（邮件 newsletter → Atom feed，3.1k★）、`twitter/the-algorithm`（排序工程参考）。**未取到**：用户提到的 `streambatch`、以及"小红书/抖音软广标注数据集"（不存在公开可下载的通用标注集，需自建）。

# A. 多样性 / 反信息茧房重排

## A1. 经典算法与指标

### A1.1 MMR（Maximal Marginal Relevance）

- 出处：Carbonell, J. G., & Goldstein, J. *The Use of MMR, Diversity-Based Reranking for Reordering Documents and Producing Summaries*. SIGIR '98, pp. 335–336（CMU Language Technologies Institute）。[来源: https://doi.org/10.1145/290941.291025]
- 原文 PDF 可达（本环境无法解析 PDF 正文，仅确认链接存在）：[来源: https://ciir.cs.umass.edu/pubfiles/ir-133.pdf]
- 公式要点（标准形式）：
  - 逐轮从候选集 `R \ S` 中选出
    `d* = argmax_{d∈R\S} [ λ · sim(d, q) − (1 − λ) · max_{s∈S} sim(d, s) ]`
  - `λ` 是相关性/多样性权衡（λ=1 退化为纯相关性排序，λ=0 退化为纯冗余最小化）。
  - 典型 `sim` 用余弦相似度（向量检索时用 embedding 归一化内积）。
- 工程含义：**多样性不是"再排一次"，而是在选的时候就不选已选过的东西**。这正是"每天 N 条只来自 3 个话题"的对症解法。

### A1.2 α-NDCG（评估侧：带冗余惩罚的子主题覆盖）

- 出处：Clarke, C. L., Vtyurina, A., & Ashpool, C. *Novelty and diversity in information retrieval evaluation*. SIGIR '08. [来源: https://doi.org/10.1145/1390334.1390446]
- 公式要点（标准形式）：对每个子主题 `t` 的第 `j` 个相关结果给增益 `α^(j−1)`（α<1 ⇒ 同一子主题重复出现收益递减），再按 `gain / log2(rank+1)` 折扣累加：
  `DCG_α = Σ_i ( Σ_{t∈T_i} α^(j−1) · (1 − rel_{i,t}) ) / log2(i + 1)`
  即：**每个子主题只算第一次最赚，之后迅速贬值**；α 越大越鼓励覆盖更多子主题。
- TREC Novelty Track 的规范评测任务（"新颖性 = 已知信息之外的发现"）出处：[来源: https://doi.org/10.6028/nist.sp.500-261.novelty-overview]、[来源: https://doi.org/10.6028/nist.sp.500-251.novelty-overview]、[来源: https://doi.org/10.3115/1220575.1220589]。
- 与本项目的关系：α-nDCG 是**离线评估指标**，可以直接拿来做"我这套每日简报是否覆盖了足够多话题"的离线打分函数（见 A5.5）。

### A1.3 xQuAD（评估侧：按子主题的理想排名加权覆盖）

- 出处：Santos, R. L. T., Macdonald, C., & Ounis, I. *Exploiting query reformulations for web search result diversification*. WWW '10. [来源: https://doi.org/10.1145/1772690.1772780]
- 公式要点（标准形式）：在 top-k 内，统计**被覆盖的不同子主题数**；一个文档若覆盖多个子主题，则按 `1/|该文档覆盖的子主题数|` 分摊贡献；每个子主题另有一个"理想排名阈值" `b_t`（若该子主题在 ground-truth 中第 `b_t` 位就满足），未进入 `b_t` 的覆盖不计分。直觉：**覆盖得早比覆盖得晚值钱**。
- 未取到：xQuAD 官方评测脚本与 TREC Diversity Track overview 正文（`trec.nist.gov` 发生跨域跳转，未取到）。使用前建议核对原文公式。

### A1.4 来源多样性 / 来源可信度先验

- 来源可信度先验的一手实现参考：Ni, S., Bu, L., & Markov, I. *Prioritizing Original News on Facebook*. CIKM '21. [来源: https://doi.org/10.1145/3459637.3481943]（核心思想：把"原创新闻源"作为一个可提升的排序特征，而非依赖人工白名单）。
- 落地做法：给每个来源维护 `credibility ∈ [0,1]`（原创度/转载链长度/历史事实性），在排序分里作为乘性或加性先验；同时用**来源计数上限**（每来源每日最多 1–2 条）实现"来源多样性"——这是成本最低、最可解释的多样性约束。

### A1.5 突发性（burstiness）

- 用途：识别"正在爆发"的话题与"背景噪声"。常用工程定义：短时间窗出现次数的方差/均值比，或 短窗速率 / 长窗速率；配合泊松/负二项显著性判定。
- **未取到**：burstiness 的规范论文出处（Catlott/Manning 一系在本环境无法准确定位；arXiv/Crossref 检索未命中可信条目），故本文件不引用具体文献，只采用上述通用定义。

### A1.6 新颖性与时间衰减

- 新颖性：在候选阶段与"已读集合"比，而不是与"当天集合"比（否则第二天所有内容都"不新颖"）。可用 SimHash/MinHash 查近 30 天指纹库。
- 时间衰减：`recency = exp(-λ·Δt)`（半衰期 `h = ln2/λ`）；热点条目可用 burstiness 修正，避免"旧帖被反复转发"霸榜。
- 与 burstiness 的组合在工程上通常写作 `score = base · recency · (1 + β·burst)`。

### A1.7 惊喜配额（serendipity）

- 出处：Zhang, Y. T., Bell, K., & Baldwin, K. *Auralist*. WSDM '12（引入 serendipity 的音乐推荐工作）。[来源: https://doi.org/10.1145/2124295.2124300]
- 落地做法：在每日简报里固定留 1–2 个"与你兴趣弱相关但评分不低"的槽位（用兴趣画像距离度量 novelty，用流行度兜底质量），并给用户一个"不感兴趣"反馈入口。

## A2. 学术证据：filter bubble / echo chamber

| 研究 | 设计与规模 | 可引用结论 | 来源 |
|---|---|---|---|
| Bakshy, Messing & Adamic 2015, *Science* | Facebook 全量用户曝光/点击日志 | 朋友分享的跨立场新闻显著更少；**算法排序导致信息流中跨立场内容减少约 15%**，用户对跨立场内容的**点击减少约 70%** → 茧房 = 选择性暴露 + 选择性点击的乘积 | https://doi.org/10.1126/science.aaa1160 |
| Nyhan et al. 2023, *Nature* | 2020 美国大选期间 Facebook **多波次现场实验**，23,377 名用户 | 把"同温层"来源曝光降低约 **1/3** → 跨来源曝光↑、不文明语言↓，但**八项预注册态度指标（情感极化、意识形态极端化、候选人评价、错误信念等）无可测变化** → 曝光结构 ≠ 态度 | https://doi.org/10.1038/s41586-023-06297-w |
| Guess et al. 2023, *Science* | Facebook/Instagram 时间序 vs 默认算法，3 个月 | 时间序**显著减少使用时长与活跃度**；**政治内容与不可信内容同时增加**；Facebook 上不文明/脏话内容减少、来自"温和朋友"和"受众混合来源"的内容增加；**议题极化/情感极化/政治知识无显著变化** | https://doi.org/10.1126/science.abp9364 |
| Huszár et al. 2022, *PNAS* | Twitter 平台级 RCT（近 200 万日活账号切换到无个性化的反向时间序 feed），7 国立法者 + 620 万篇美国新闻 | **7 国中 6 国主流右翼的算法放大高于主流左翼**；美国媒体景观中算法放大**偏向右倾新闻源**；**未发现**极端派比温和派被放大更多的证据 | https://doi.org/10.1073/pnas.2025334119 |
| Milli et al. 2025, *PNAS Nexus* | Twitter **预注册算法审计**（对比反向时间序基线） | 按互动排序会放大**情绪化、敌视外群体**的内容；**用户并不偏好算法选出的政治推文**（说明互动目标与用户偏好不一致）；改用"陈述偏好"排序可减少愤怒/党派敌意内容，但可能强化"符合自身立场"的内容 | https://doi.org/10.1093/pnasnexus/pgaf062 |
| González-Bailón et al. 2023, *Science* | Facebook 全量政治新闻曝光 | 标题即结论：Facebook 上政治新闻曝光的**意识形态隔离是不对称的**（只取到题录，摘要未取到） | https://doi.org/10.1126/science.ade7138 |
| Pennycook et al. 2021, *Nature* | 4 个调查实验（N=3,485）+ Twitter 现场实验（N=5,379） | 让人"想到准确性"会显著提升后续分享的新闻质量 → **注意力提示是比改排序更便宜的干预** | https://doi.org/10.1038/s41586-021-03344-2 |
| Allcott et al. 2020, *AER* | Facebook 停用 4 周（2018 中期选举前）RCT | 停用降低了**事实性新闻知识**与**政治极化**，并提升主观幸福感 → 消费时长不是"茧房"的充分统计量 | https://doi.org/10.1257/aer.20190658 |

**对本项目的三条可操作推论**

1. 不要指望"换排序"能改变用户信念；要做的是**让用户看见结构**（每条标注来源与话题簇、给出"为什么推给你"）。Pennycook 的"注意力提示"结论支持"在简报顶部加一句准确性/多样性提示"。
2. 时间序不是免费午餐（Guess et al.：不可信内容同时变多）。因此本项目应采用**"时间序底稿 + 配额筛选"**，而不是纯时间序。
3. 互动量不能当质量代理（Milli et al.：算法选的互动内容用户并不喜欢）。所以排序分里**不要放原始点赞/热度**，或必须做归一化。

## A3. 落地工程做法

### A3.1 跨源去重

| 方法 | 原理 | 适用 | 来源 |
|---|---|---|---|
| URL 规范化 + 正文哈希 | 归一化 URL、去 query 参数、标题+正文 sha | 完全转载（最快，先做） | 工程常识 |
| SimHash | 把特征哈希成 64 位指纹，汉明距离 ≤ k 判重 | 近重复、模板化改写 | Charikar, STOC'02 [来源: https://doi.org/10.1145/509907.509965] |
| MinHash + LSH | Jaccard 近似，按 band 召回 | 集合型相似（标题 shingle、标签集合） | Broder, SEQUENCES'97 [来源: https://doi.org/10.1109/sequen.1997.666900] |
| TF-IDF / BM25 | 词级余弦 | 短文本、关键词差异明显 | Salton & Buckley, IP&M 1988 [来源: https://doi.org/10.1016/0306-4573(88)90021-0] |
| Embedding 余弦 | 语义近似 | 改写/翻译/同事件不同叙述 | 见 A3.5 选型 |

**组合建议（成本从低到高）**：URL/标题精确 → SimHash(近重复) → MinHash-LSH(集合) → embedding(语义)。embedding 只对"疑似重复"候选做二次确认，避免 O(N²)。

### A3.2 主题聚类 + 每簇配额

- 聚类：BERTopic（Transformer 嵌入 + c-TF-IDF + HDBSCAN）[来源: https://github.com/MaartenGr/BERTopic]；X 官方算法里用的是 SimClusters（社区发现 + 稀疏嵌入，把用户/推文投到 ~145 个社区）[来源: https://github.com/twitter/the-algorithm]，说明"社区发现做多样性"是工业标准做法。
- 配额算法（推荐顺序）：
  1. **轮转配额**：把当天 top-M 话题簇按轮转取，每簇取 `q = floor(K / |C|)`，剩余名额按簇内最高分补。
  2. **带新颖度的配额**：每取一条，其与已选集合的相似度进入惩罚（≈ MMR，但硬约束为"每簇最多 n 条"）。
  3. **多样性最大化子集选择**：DPP（determinantal point process）视角——与 CDM 论文中"MMR 是 DPP 的贪心近似"的讨论一致 [来源: https://arxiv.org/abs/2406.09021]。
- 注意：**簇太多**会把每天切成碎片。建议先做"粗簇 + 细簇"两级：粗簇决定配额，细簇内部排序。

### A3.3 来源可信度先验

- 用原创度而非白名单：把"转载链长度、首发时间、是否有署名机构"做成特征（参考 CIKM'21 原创新闻排序 [来源: https://doi.org/10.1145/3459637.3481943]）。
- 社交源（小红书/B站）默认低先验，媒体源默认高先验；对"同一事件"取可信度最高的那条作为主条目，其余折叠为"相关报道"。

### A3.4 LLM 辅助的分组 / 摘要 / 重排

- 重排：RankGPT 用"生成排列 + 滑窗"把 LLM 变成零样本重排器，并用 permutation distillation 蒸馏成小模型（440M 蒸馏模型在 BEIR 上超过 3B 监督模型）[来源: https://arxiv.org/abs/2304.09542]（代码仓库见论文摘要给出的 `www.github.com/sunnweiwei/RankGPT`）。
- 蒸馏路线：MMR 当老师 → 轻量学生模型（KDD'24，快手线上 A/B 通过）[来源: https://arxiv.org/abs/2406.09021]。
- 分组/命名：LLM 给簇起人类可读名字、给同簇多条生成一句"合并摘要"（成本可控：每天 M≤12 个簇，每簇 1 次调用）。
- 成本边界：**LLM 只做 M 个簇的命名与 K 条最终摘要（K≈20）**，不参与全量打分。

### A3.5 兴趣画像（按已定产品决策：**显式为主 + 轻量隐式 + 配额兜底**）

> 产品侧已定：**不做向量画像、不做 LLM 兴趣推断**（见 `.scratch/radar/map.md`）。本节按该约束给出可落地形态。

- 三层结构（全部本地可算、可解释、可回滚）：
  1. **显式（主）**：主题订阅、关键词订阅、来源白/黑名单、显式"不想看 XX"。每个主题一个权重 `w_topic ∈ [0,1]`，由订阅动作直接写入。
  2. **隐性（辅，量很小）**：只用两个信号——**点开**（`w_topic += α`）与**不感兴趣**（`w_topic -= β`，并把该主题配额降一档）。不使用停留时长、向量、LLM 推断，避免不可解释与不可控。
  3. **配额兜底（地板）**：无论兴趣权重多高，单一主题的条数上限由硬配额约束（见 A5「多样性硬指标」），保证"再喜欢也不会茧房"。
- 主题判定靠**规则 + 聚类簇名**，不用向量画像：`topic(item) = 命中的订阅主题`（关键词/来源规则），否则 `= 该条所属聚类簇`。
- 显式权重覆盖隐性（论文证据：用户声明偏好与算法互动偏好不一致，且用户更信前者 [来源: https://doi.org/10.1093/pnasnexus/pgaf062]）。
- 隐式权重的**衰减**：长期未点击的主题按 `exp(-λ·Δt)` 衰减（见 A1.6），避免一次点击长期锁死兴趣。

### A3.6 惊喜配额（serendipity）

- 槽位：每天 1–2 条，选取条件为 `novelty(topic, profile)` 高 且 `credibility` 不低于阈值；用 Auralist 的 serendipity 思路 [来源: https://doi.org/10.1145/2124295.2124300]。
- 反馈闭环：若用户对惊喜条目点击率显著低于均值，降低惊喜配额（自适应性，但设下限 0，避免退化成纯兴趣流）。

## A5. 每日 pipeline 草案（N → 简报）

目标：每天从 N≈500 条原始条目，产出 1 份 15–25 条的简报，覆盖 ≥8 个不同话题簇，每簇 ≤3 条。

| # | 步骤 | 算法/工具 | 需要 LLM？ |
|---|---|---|---|
| 1 | **采集与归一化** | RSS/API/抓取 → `feedparser` 解析、`trafilatura` 抽正文；统一 URL/标题/时间/来源/作者/语言 | 否 |
| 2 | **硬过滤** | 时效窗口（近 48h）、来源白/黑名单、最小正文长度、敏感/垃圾规则 | 否 |
| 3 | **跨源去重** | URL+标题精确 → SimHash(Hamming ≤ 3) → MinHash-LSH → embedding 余弦二次确认；保留每簇的"代表条目"与其余作为 related | 否 |
| 4 | **主题聚类** | embedding（中文优先）→ BERTopic/HDBSCAN 出粗簇；簇名可由 LLM 命名（见第 5 步） | 否（先纯算法） |
| 5 | **簇命名 + 合并摘要** | 默认离线抽取式（正文首句 / 标题改写）；检测到用户自备 LLM key 才升级为 LLM 命名+摘要（每粗簇 1 次调用，M≈10–12 次/天） | ⚪ 可插拔，默认否 |
| 6 | **打分（簇内）** | `score = w_r·interest + w_c·credibility + w_n·novelty + w_t·recency·(1+β·burst) + w_h·heat − w_d·redundancy`；`interest` = **主题权重表查表**（A3.5，不做向量画像）；可信度来自 A1.4 先验；新颖度用 SimHash/MinHash 查 30 天指纹库；`heat` 来自源自带热度字段（口径见票 04 的字段契约） | 否 |
| 7 | **配额分配（多样性核心）** | 每簇上限 `n_max=3`；总条数 K；按"轮转 + 簇内分数"分配；执行 MMR 软惩罚避免同源扎堆 | 否 |
| 8 | **排序（簇间）** | 用 MMR 在候选集上贪心：`argmax [λ·score − (1−λ)·max_sim_to_selected]`，λ≈0.7（相关优先、留 30% 给多样性） | 否 |
| 9 | **惊喜槽位** | 插 1–2 条 `novelty` 高且 `credibility` 达标的内容；受"每簇上限"约束 | 否 |
| 10 | **可选 LLM 重排** | 只对最终 K 条用 RankGPT 风格重排；**需用户自备 key**，无 key 时跳过且功能完整 | ⚪ 可插拔，默认否 |
| 11 | **简报渲染** | 分组标题 + 每条 1–2 句摘要 + 来源 + 话题簇标签 + **"为什么推给你"**（订阅主题/热点/惊喜）；摘要同样走可插拔接口 | ⚪ 可插拔，默认否 |
| 12 | **反馈落库** | 记录曝光/点开/跳过/"不感兴趣" → 更新**主题权重表**（A3.5）与簇配额权重（不存向量画像） | 否 |

**离线评估（用 α-NDCG / xQuAD）**：把当天 K 条简报当作 top-k，用人工标注的"该条目属于哪个子主题 + 子主题的理想排名"计算 α-nDCG / xQuAD，跨天比较调 λ、n_max、簇数量 [来源: https://doi.org/10.1145/1390334.1390446]、[来源: https://doi.org/10.1145/1772690.1772780]。

**同时要埋的"茧房仪表"**（每日记录，用于自我纠偏）：
- 话题簇熵、来源熵、Top-1 源占比、重复率（被去重条数/总条数）、惊喜条目占比、用户主动打开率。
- 依据：证据显示"曝光结构调整"本身是可测的（Bakshy 15%、Nyhan 1/3、Guess 时间序），把同样的量测放到自己身上。

**多样性硬指标（与已定成功标准对齐）**

口径定义：**分母 = 当日展示条数 K**（正常日 K=20）；配额类指标同时给出绝对条数上限，避免 K 变化时百分比跳变。

| 指标 | 目标 | 换算到 K=20 | 达成手段 |
|---|---|---|---|
| 单一来源占比 | ≤25% | 同一来源 ≤5 条 | 来源配额 `n_max_src = 5`（硬约束） |
| 单主题占比 | ≤30% | 同一主题簇 ≤6 条 | 主题配额 `n_max_topic = 6`（硬约束） |
| 跨源重复事件 | ≤10% | 同一事件跨源重复 ≤2 条 | 去重后每事件只留 1 条代表，其余折叠为"相关报道" |
| 软广误杀率 | ≤5% | 每 20 条最多误伤 1 条 | 见 B3/B4 三档：只有高置信不展示，中置信一律展示+标注 |

> K < 20 的当天按**绝对条数**执行（K=12 时：单源 ≤3、单主题 ≤3、跨源重复 ≤1），并把当天的实际 K 记进指标看板。

**冷启动（无点击历史、无订阅）**：此时"茧房"完全来自**源的组合**而非用户画像，所以多样性比个性化更重要：
1. 用**默认主题集**（用户勾选的几个大类 + 源自带分类）而非个性化分数；
2. 纯多样性配额兜底（单源/单主题上限照常生效）；
3. 排序主要靠**热度 + 可信度 + 新颖度**；
4. 冷启动期不启用惊喜槽位（没有画像判断"惊喜"）。

### B1.3 软广的产业化证据（说明为什么不能用"读起来真实"当判据）

- 小红书 KOC（关键意见消费者）被品牌方/营销方雇佣产出"广告种草内容"，并**刻意让这类内容看起来像普通用户的自发分享**，同时这类劳动在合同与平台机制中被低估[来源: https://arxiv.org/abs/2409.08360]。
- 抖音/电商直播中的规避话术：中文电商直播间存在"谐音/变形词"规避审查的现象（LiveAMR 任务与 86,790 条数据集，首个面向中文电商直播的"morph 识别"数据集）[来源: https://arxiv.org/abs/2512.23280]。
- 推论：**软广检测的核心不是文本风格，而是"是否存在商业关系"的间接证据**（平台任务、组件、账号历史），文本关键词只能当"召回器"，不能当"判定器"。

## B2. 现有算法做法与开源实现（对比）

| 方案 | 做法 | 召回 | 精度 | 成本 | 适用 |
|---|---|---|---|---|---|
| **① 规则/关键词打分** | 关键词表 + 句式 + 数字模式 + CTA 模式，加权求和 | 高（词表宽时召回好） | 低中（"人均"在真实探店里也常见） | 极低 | 候选召回的第一道闸 |
| **② 结构化字段规则** | 广告标识/星图蒲公英报备/团购组件/链接/认证 | 低但**极准**（官方任务基本等于答案） | 极高 | 低（需能读到详情字段） | 应作为**一票否决/加权主信号** |
| **③ 账号画像** | 近 30 天商业特征比例、模板化程度、同矩阵 | 中 | 中高 | 低（需历史累积） | 对"养号"型软广最有效 |
| **④ 文本分类器（有监督）** | 中文 encoder 微调（二分类/多标签） | 中高 | 高（域内标注充足时） | 训练一次、推理极低 | 主力；需要自建标注集 |
| **⑤ LLM 打分（提示词）** | 给结构化字段 + 文案，让 LLM 输出 0–1 广告概率与理由 | 高 | 中（域内提示词不可靠，见 XHS-SCoRE） | 高（每条一次调用） | **只做可选的中置信复核/判据解释**，不做全量判定；无 key 时该环节整段跳过 |
| **⑥ 蒸馏版 LLM 判别器** | 先用 LLM 标注 → 蒸馏到小模型（参考 RankGPT 的 permutation distillation）[来源: https://arxiv.org/abs/2304.09542] | 中高 | 中高 | 低（推理） | 规模化中置信判定的正解 |
| **⑦ 评论侧信号** | 评论语义聚类（"多少钱/怎么去"占比） | 中 | 中高 | 中（需评论数据） | 补充证据，不宜单独定罪 |

**关于"有标注数据的小红书广告数据集是否存在"**：
- **不存在公开可下载的通用"小红书软广标注集"**（本次未取到；HF 数据集 API 在本环境不可达，GitHub 检索仅命中医疗广告违规集 FMAVD）。
- 可用的近似资源：
  1. **XHS-SCoRE**（小红书文本标注基准，任务是"社会比较"而非广告，但证明"小红书域内标注 + 中文 encoder 可行、提示词 LLM 不可行"）[来源: https://arxiv.org/abs/2605.01017]；
  2. **FMAVD**（中文医疗广告细粒度多标签违规集，可借鉴标注维度设计）[来源: https://github.com/FuWeiru/FMAVD]；
  3. **LiveAMR**（中文电商直播规避话术数据集，86,790 样本）[来源: https://arxiv.org/abs/2512.23280]；
  4. **NLPCC 中文微博语料**的组织与标注流程模板 [来源: http://tcci.ccf.org.cn/conference/2014/pages/page04_dg.html]。
- 结论：**必须自建标注集**（下文 B3 给出协议）。

**方案选择建议（针对本项目）**：②（结构化硬信号）→ ①（关键词召回）→ ③（账号画像）→ ④（自训分类器做主力）→ ⑤（中置信的**可选** LLM 复核）。理由：证据显示纯提示词 LLM 在中文小红书文本上系统性失效 [来源: https://arxiv.org/abs/2605.01017]，且小红书软广本身就以"伪装成真实分享"为核心对抗手段 [来源: https://arxiv.org/abs/2409.08360]——所以判定主力必须是**结构化 + 规则 + 自训小模型**，LLM 只能作为可选增强。

## B3. 评估方法（可操作协议）

### B3.1 "软广告"的操作性定义

标注时用**三分类 + 明确判据**，避免"像不像广告"的直觉：

- **A 类｜明确商业广告**：满足任一即可判 A
  1. 平台/账号已标明广告、商业合作、星图/蒲公英报备；
  2. 存在购买入口（团购、商品、外链、下单、客服、私域引流）且内容为推荐/测评/探店体裁；
  3. 作者与被推荐主体存在可查的利益关系（同一主体注册账号、品牌员工、MCN 旗下）。
- **B 类｜疑似软广（无标识）**：无 A 类任一硬证据，但同时命中 ≥2 个"商业化模式"信号（固定优惠话术、行动号召、私域引流模板、同店模板化复刻、与账号历史商业内容占比高），且缺乏"真实体验特征"（无缺点、无排队/价格波动/踩坑描述、评论无负评）。
- **C 类｜真实 UGC**：有可验证的个人体验细节（时间、排队、踩坑、与他人对话、价格/口味具体差异、评论有正负两面）。
- **C2｜品牌自营探店**（单独一类）：主体是商家自己的账号（企业号 / 认证商家 / 品牌自营），内容即自有商品的自述。它**属于"广告"但不是"软广"**：法律上依第九条应标明；标注时按 A 处理，但在训练分类器时**必须与"第三方软广"分开**，否则模型会把"商家号"学成"真实体验"，误伤真实个人笔记。
- **判不准｜U（unknown）**：文本过短（<20 字）、纯图片无文案、语境缺失 → 单独一类，**不计入 FN**，但单独统计比例（数据质量指标）。

> 关键：把"是否**有商业利益**"与"是否**像广告**"分开问。前者是法律事实（可查平台任务/组件），后者是文体印象（不可靠）。

### B3.2 抽样与标注

1. **分层抽样**：按 (平台 × 是否有 POI/组件 × 关键词命中 × 账号类型) 分层，避免全是极端样本；正负各 ≥200 条，总量建议 500–800 条起步。
2. **双人独立标注 + 第三人仲裁**；报告 **Cohen's κ**（分类型别算）。参考：主观性较强的"多样性/可读性"判断 κ 可能低至 ~0.2 [来源: https://arxiv.org/abs/2002.12457]，软广判定有硬判据、可望更高；若 κ < 0.6，先改判据（写细则 + 例子）再重标，不要硬凑。
3. **判据手册**：每个 A/B/C 各写 5 个正例 + 5 个反例（含易混淆对，如"真的推荐了一家便宜店 vs 收钱推荐"）。
4. **漂移监控**：每周从生产数据随机抽 30–50 条复标，监控标注一致率与 A 类占比变化（平台规则/营销话术会变）。

### B3.3 指标与阈值

- **主指标**：PR 曲线 + `precision@K`（K=展示条数，如每天 20 条）与 `recall`；不要只看 F1（正负极不平衡时 F1 会骗人）。
- **产品验收口径（已定）：软广误杀率 ≤5%**。定义："被过滤或被折叠、但人工判定为真实 UGC 的条数 ÷ 被过滤+被折叠的总条数"——即**留在用户面前那部分内容的精度**。误杀率是硬指标，漏放率是软指标。
- **代价取舍（明确站边）**：**宁可漏放并标注，不可静默误杀**。理由：(1) 漏放一条软广的代价是"用户被推销一次"，一次性且可逆；(2) 误杀一条真实好店是**永久损失一个可用候选**（好店本来就稀缺），且会系统性削掉长尾小店的可见度，反而制造新的信息偏食。因此策略是"**只有高置信才不展示；中置信一律展示但标注**"，而不是"疑似即隐藏"。
- **阈值求解**：不手调阈值，而是**由误杀率反解**：在验证集上取满足"误杀率 ≤5%"的最高阈值 τ（要留余量则按 ≤2.5% 求 τ）；同时输出 τ±0.05 的宽松/严格档供用户自选。
- **成本换算**：用"每天误杀 1 条 = 一年损失 365 条候选"解释一侧，用"每天漏放 1 条 = 一年 365 次推销打扰"解释另一侧，把取舍摆在台面上而不是藏在阈值里。

### B3.4 回归测试与上线门槛

- 固定一份 **冻结回归集**（含历史误杀样本），每次改权重/换模型必须跑：precision/recall 不低于基线，且误杀数不增加。
- 上线门槛：灰度一周 → 每日人工复核 20 条 → 误杀 >2 条/天则回滚调阈值。

## B4. 过滤 pipeline 草案 + 初始权重

### B4.1 流程

```
抓取/详情落库
  → 规则硬过滤（时间窗、黑名单、重复）
  → S1 结构化广告判定（平台"广告"标识 / 星图·蒲公英报备 / 官方商业组件）──→ 高置信档
  → S2 文本商业特征（关键词 / 句式 / 数字 / 行动号召 / 引流话术）
  → S3 账号画像（商业内容占比、模板化、认证）
  → S4 互动与评论异常
  → S5 语义分类器（自训；标注集未就绪时降级为纯规则）
  → 硬信号 + 加权总分 → 三档判定（对齐已定产品决策）
       高置信  → 不展示（进入"已过滤"清单，可查、可申诉）
       中置信  → 展示但降权 + 折叠 + 标注「疑似推广」
       不确定  → 展示但折叠 + 标注「信息不足」，绝不静默过滤
  → 输出 + 逐条记录每个信号的分值（判据可解释）
```

### B4.2 初始权重建议（先验起点，必须用自建标注集重标定）

**先走"硬信号通道"（不参与加权）**

| 硬信号 | 判档 | 说明 |
|---|---|---|
| S1a 平台/账号"广告 / 商业合作 / 星图·蒲公英报备"标识 | → 高置信（不展示） | 官方标记即事实，最可靠 |
| S2a 引流话术（私信 / 加V / 公众号 / 群 / 留链接） | → 高置信（不展示） | 商业引流是《互联网广告管理办法》语境下的可识别广告行为 |

**再走"加权通道"（权重和 = 1.00）**

| 特征 | 权重 | 触发条件（示例） | 备注 |
|---|---|---|---|
| S1b 商业组件（团购 / 商品 / 外链 / 下单 / 门店预订） | 0.22 | 存在任一购买入口 | 与"探店/测评体裁"共现时权重×1.5 |
| S2b 优惠/价格话术密度（团购/秒杀/人均/特价/折扣） | 0.10 | ≥2 词或 ≥1 句式 | 权重刻意低以控误伤（"人均"在真实笔记里常见） |
| S2c 行动号召（赶紧冲 / 手慢无 / 评论区扣1 / 记得点赞收藏） | 0.06 | 命中 | — |
| S2d 体裁伪装声明（不是广告 / 自费探店 / 无广） | 0.05 | 命中 | 与商业组件共现时升为 0.10 |
| S3a 账号近 30 天商业特征占比 | 0.22 | ≥50% → 满分，线性插值 | 需历史累积；冷启动按缺失处理 |
| S3b 模板化 / 同店复刻 | 0.07 | 命中 | — |
| S4a 评论语义分布（问价 / 求地址 / 怎么去 占比） | 0.15 | ≥30% | 需评论数据，缺失则不计 |
| S4b 点赞/评论比异常高 | 0.05 | 命中 | 弱信号 |
| S5 语义分类器概率（自训中文 encoder） | 0.08 | 模型输出 | 标注集未就绪时该行置 0 并重新归一化 |

**三档阈值**

| 条件 | 档位 | 呈现 |
|---|---|---|
| 硬信号命中（S1a 或 S2a） | 高置信 | **不展示**；进"已过滤"清单（可查、可申诉） |
| 加权 `score ≥ 0.70`，且**≥2 个独立信号族**同时命中 | 高置信 | 不展示 |
| `0.45 ≤ score < 0.70`，或只命中 1 个信号族 | 中置信 | **展示但降权 + 折叠 + 标注「疑似推广」** |
| `score < 0.45` | 低置信 | 正常展示 |
| 可用权重 < 0.6（信号大面积缺失） | 不确定 | 展示但折叠 + 标注「信息不足」，**不静默过滤** |

> 为什么要"≥2 个独立信号族"才能进高置信：单一弱信号（尤其 S2b/S4b）误伤真实探店笔记的概率高，而误杀是硬指标（≤5%）。独立信号族指：结构化字段 / 文本话术 / 账号画像 / 互动评论，四族互不相关。

### B4.3 信号缺失时的降级规则（重要）

1. **权重重归一化**：缺失特征的权重不记 0，而是从总分中剔除并把剩余权重归一化（否则缺字段会被当作"不像广告"）。
2. **可信度上限**：若总可用权重 < 0.6（即一半以上信号缺失），**不下结论** → 走"不确定"档：展示 + 折叠 + 标注「信息不足」，**绝不静默过滤**（这正是已定产品决策里"信号缺失按不确定处理"的实现）。
3. **缺失偏置校正**：结构化字段（广告标识/组件）常因抓取失败而缺失 → 缺失时把 S2+S3 的相对权重上调 20%，并把阈值 τ 上调 0.05（少过滤、更保守），同时记录 `missing_structured=true`。
4. **文本过短 / 无文案**：直接标 `unknown`（不确定档），不判中置信（避免用短文案臆断）。
5. **账号冷启动**：无历史画像时 S3a 权重置 0 并重新归一化，转而依赖"是否有 POI/是否有组件"等可得信号。
6. **每日输出质量看板**：高置信过滤率、中置信占比、不确定占比、各信号缺失率。任一项异常（不确定占比 >30% 或结构化缺失率 >20%）→ 触发抓取/解析修复，而不是改权重。
7. **用户反馈闭环**：用户标记"这条是广告/这条是真的"直接进标注池；每周一次权重微调，单次调整幅度 ≤10% 以免震荡，且必须跑冻结回归集（B3.4）。
8. **中置信不等于软广**：中置信条目照样展示并标注"疑似推广"，同时把它作为**弱负反馈**（该主题权重轻微下调），让系统自己学会"这类话术在我这里不是我想看的"。

### B4.4 与地图模块的衔接

- **三档而非硬过滤**：真实用户的自发热笔记（"这家真好吃"）常常也带 POI，若阈值过严会得到空地图。因此把 `score` 同时当作**排序特征**（低分排后）与**呈现标记**：
  - 高置信 → 不展示；
  - 中置信 → 保留但降权、折叠、标注「疑似推广」（用户可展开自己判断）；
  - 不确定 → 保留、折叠、标注「信息不足」。
- 与"注意力提示"干预一致：与其替用户静默判断，不如让用户看到判据并自己决定（呼应 Pennycook et al. 的"让人注意到准确性"能改变分享质量 [来源: https://doi.org/10.1038/s41586-021-03344-2]）。
- 地图侧可另加一个开关：**"只看高置信真实内容"**（严格模式，用户主动选择误杀代价），与默认的宽松三档并存。

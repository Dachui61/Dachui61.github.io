# 3. 纯静态，不引入后端

- 状态：已接受
- 日期：2026-11-22
- 相关决定：2、4

## 上下文

GitHub Pages 只托管静态文件。它没有服务端运行时，没有 API routes，
没有数据库，没有函数。这是平台的硬限制，没有任何配置能绕开。

本站是个人展示站，内容在构建期已经全部确定，所以这个限制并不难受。
但它确实排除了几类功能，需要明确记下来，免得日后反复讨论。

## 决策

本站**不引入任何后端**。所有功能必须在构建期完成，或者在浏览器里完成。

因此：

- **搜索**用构建期生成的静态索引（Pagefind），不是服务端 API。
  AIHero.Dev 的 ⌘K 搜索是服务端的（cmdk 面板 + 200ms 防抖 + `/api/search`），
  本站做不出同样的东西，但静态索引在效果上等价，成本为零。
- **没有订阅表单**。订阅意味着存邮箱，意味着后端。本站不做。
- **没有评论、没有访问统计服务端**。
- 内容源在构建期定死（决定 2），页面加载后不再请求任何数据接口。

## 后果

- 如果日后要做「留邮箱」「订阅」「看谁在线」这类功能，本站必须换托管
  ——迁到 Cloudflare Pages、Vercel 或 Netlify，或者让 GitHub Pages 只托管
  前端、把后端放在别处。**这会是本站最大的一次改动**，所以这个决定要
  在建站时就想清楚，而不是等到需要时再发现。
- 好处是：没有后端就没有后端的运行成本、没有数据库要备份、没有密钥要
  泄漏、没有一个能被人打挂的服务。Free 计划下 GitHub Pages 的部署还
  不消耗 Actions 分钟。

## 备选方案（被否掉的）

| 方案 | 否掉原因 |
|---|---|
| Pages 托管前端 + Cloudflare Workers 做后端 | 现在没有需要后端的功能；提前引入两套部署、一套凭据管理 |
| 直接用 Vercel / Netlify | 它们能跑服务端，但本站用不上；Pages 免费且部署不耗 Actions 分钟，够用 |

# 4. 双语：默认语言不带前缀

- 状态：已接受
- 日期：2026-11-22
- 相关决定：1

## 上下文

本站要中英双语。URL 怎么安排决定了三件事：分享出去能不能打开、搜索
引擎能不能分别收录两种语言、切换语言时会不会把当前页面弄丢。

有三种做法：

- **A：默认语言不带前缀**。中文在 `/`，英文在 `/en/`。
- **B：两种语言都带前缀**。`/zh/` 和 `/en/`。
- **C：单一 URL，客户端切换**。语言存在 localStorage 里。

## 决策

用 **A**：默认语言（中文）在 `/`，另一种语言（英文）在 `/en/`。

`astro.config.mjs` 里：

```js
i18n: {
  defaultLocale: 'zh',
  locales: ['zh', 'en'],
  routing: { prefixDefaultLocale: false },
}
```

页面文件按语言分目录放：`src/pages/index.astro` 是中文首页，
`src/pages/en/index.astro` 是英文首页，其余同理。切换器把当前路径映射
到另一种语言的前缀。

## 后果

- **中文是默认**，因为它先落地，访客第一眼看到的是中文。这是有意的
  选择，不是顺手的结果。
- **英文页有独立 URL**，可以被搜索引擎分别收录，也可以在社交平台单独
  分享。`<link rel="alternate" hreflang>` 已配好。
- **代价**：URL 本身不总是自解释的——`/work/vitals/` 是中文，
  `/en/work/vitals/` 是英文。同一个页面有两个地址。
- **不能用单一 URL + 客户端切换**（方案 C）：那样切换后刷新会丢失语言，
  而且两种语言抢同一个 URL，对收录不利。
- **没有用「两种语言都带前缀」**（方案 B）：中文站不需要 `/zh/` 这种
  多余的前缀，URL 更短更干净。

## 备选方案（被否掉的）

| 方案 | 否掉原因 |
|---|---|
| 两种语言都带前缀 | 中文是默认语言，`/zh/` 是多余的一层；且 `prefixDefaultLocale: false` 下的裸路径更干净 |
| 单一 URL + localStorage 切换 | 刷新丢语言；两种语言抢一个 URL；分享出去对方看到的是随机语言 |
| 只在客户端按浏览器语言分流 | 同上，且对 SEO 无贡献 |
